所有权

意义

  • C/C++ 路线（手动内存管理）： 极高性能，但开发者必须手动 malloc 和 free。一旦疏忽，就会导致空指针、悬垂指针、内存泄漏、双重释放等 bug。这些 bug 极其难以追踪，且常是安全漏洞的根源。
  • Java/Go 路线（垃圾回收 GC）： 内存安全，程序员只管 new，GC 会自动回收。但 GC 会带来运行时开销（暂停程序、回收内存），导致性能不稳定，不适合编写操作系统内核、嵌入式设备或游戏引擎这类对延迟敏感的程序。

Rust 想走一条新路：既要 C 语言的性能，又要 Java 的安全，于是所有权的概念出现了。

引用的准则

在特定作用域内，对某一块数据，只能有一个可变引用

对于可变引用，以下两种行为下会发生数据竞争
一、两个或多个指针同时访问同一个数据
1、两个可变引用同时存在

2、一个可变引用 + 一个不可变引用

二、没有使用任何机制来同步对数据的访问
对于多线程的操作，需要一个同步，若未同步就进行可变借用，往往会因为安全被拒绝编译

“对于多线程的操作，必须使用同步机制（如 Mutex、RwLock、原子类型 等）来安全地共享可变数据。如果试图在没有同步的情况下跨线程使用可变引用，Rust 编译器会在编译期直接拒绝，而不是等到运行时恐慌。”

悬垂指针

一个指针引用了内存中的某个地址，而这块内存可能以及释放**（归还给操作系统或分配器）**，并分配给另外的指针使用了，这会导致未定义行为

Deepseek：让我们看看内存中发生了什么：

由于rust先编译后运行的特点，程序会在编译时就发现这种错误，保证不会在运行时出现

指针准则为什么这么严格？

  • 防止数据竞争（data race）：两个指针同时访问同一数据，至少一个在写

  • 数据竞争会导致未定义行为，Rust在编译期就杜绝了

  • 当你读数据时，不希望有人同时在改它

结构体

类似与js里的class，但 Rust 的结构体更轻量且没有继承特性，结构体是自定义的新**类型，地位与i32、u8、String等等rust内置的类型相同**

三种大类

1，具名结构体

​ 这是最常见的结构体形式，每个字段都有名称。

2，元组结构体

类似于元组，但有名字。适用于需要给整个元组一个类型名称的场景。

3，单元结构体

没有任何字段的结构体，类似于空元组 ()。

另外，为了方便创建有重复字段的新实例，rust安排了简便语法，可以复制先前实例的某些部分，但需注意复制部分是否实现了copy

枚举与匹配控制流

枚举(Enum)

枚举是这组概念的基石，允许你定义一个类型，这个类型的值只能是几个预定义的**“变体”**（variants）中的一个。

注意变体命名和变量命名一样，需要遵守的”必须以字母或下划线开头，只能包含字母、数字和下划线”

匹配控制流(match)

JS里有switch，用来多过程匹配，rust也有类似运算符
“match 是一个极其强大的控制流运算符，它允许你将一个值与一系列模式进行比较，并根据匹配的模式执行相应的代码。它可以被看作是 C 语言中 switch 的究极进化版。”——Deepseek

match规则

  1. 穷尽性：必须覆盖所有可能的模式，否则代码无法通过编译。这防止了遗漏处理某些情况的bug。
  2. 每个分支是一个表达式：每个匹配分支 => 后面的代码块会返回一个值，整个 match 本身就是一个表达式，可以赋值给变量。

可选值枚举（option）

Option 是 Rust 标准库中定义的一个极其重要的枚举。它用于表示一个值可能存在 (Some) 或可能不存在 (None) 的概念。

为什么需要 Option？
Rust 没有 null (空值) 的概念。null 的发明者称之为“十亿美元的错误”，因为它经常导致程序崩溃。Option 是 Rust 用来代替 null 的安全方式。它强制程序员在每次使用一个可能不存在的值时，都必须显式地处理 None 的情况。

生命周期注解语法

  • 'a是一个生命周期参数（可以理解为”一段时间”）
  • x: &'a str：x的引用至少存活'a
  • y: &'a str：y的引用也至少存活'a
  • -> &'a str：返回的引用存活时间不超过'a
  • 实际含义：返回的引用存活时间，是x和y中较小的那个
